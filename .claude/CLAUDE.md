# claude-explain-books

用**动画**解释并总结技术、工程类书籍。每本书做成一个单文件 HTML + Canvas 页面，发布在 GitHub Pages（见 `DEPLOY.md`）。

目标有两个，缺一不可：

1. **解释清楚**：没读过这本书的人，看完也能理解每个概念、每个例子。
2. **总结精华**：抓住全书主线和最重要的思想，而不是逐章复述。

所有回复、页面文字都用**中文**。

## 防止 "Request too large (max 32MB)" —— 必须遵守

**根本原因：** 图片、PDF 页面、截图一旦被读进主对话，就会留在上下文里，之后每次请求都要重新发送。累积超过 32MB 就会报错，`/compact` 也只能暂时缓解。

**规则：**

1. **主对话里不读任何图片。** 不用 Read 打开 `.png` / `.jpg` 截图，也不用 Read 打开 PDF 页面。
2. **书的内容一律先转成纯文本**，再用 `grep` / `sed -n` 按需读取片段：
   - PDF：`pdftotext -layout "<书>.pdf" /tmp/<slug>/book.txt`
   - EPUB：`unzip -o -q "<书>.epub" -d /tmp/<slug>/epub`，再用 `textutil -convert txt -stdout <xhtml文件>` 合并成 `book.txt`
   - 不要一次性读完整本书的文本，按章节标题定位后分段读。
3. **页面检查默认用纯文本方式：**
   - 语法：提取 `<script>` 内容后运行 `node --check`。
   - 运行时和 DOM：用无头 Chrome 加载页面，并注入探测脚本，逐步点击 `#next`，把每一步的标题、控件是否可见等信息写进一个 `<pre>`，再用 `--dump-dom` 取文本结果：
     ```bash
     "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
       --virtual-time-budget=3000 --dump-dom "file://<页面>" 2>/dev/null | sed -n '/id="probe"/,/<\/pre>/p'
     ```
   - 探测页是临时文件，用完删除，不要提交。
4. **确实需要看画面时，交给 `visual-qa` 子代理。** 子代理有独立的上下文，截图不会进入主对话；它只返回文字结论。每次最多看 6 张、宽度压缩到 900px 以内（`sips -Z 900`）。
5. 用户发来截图时，只看必要的那一张，不要反复要求更多截图。

## 内容设计原则

### 先理解书，再设计
1. 用 `book-analyst` 子代理提取全书主线、核心概念、书中的关键例子和原文引文（带章节号）。
2. **根据这本书自身的特点选择呈现方式。** 论文集、模式语言、算法书、案例书适合的结构不同，不要套用上一本书的模板。
3. 先给用户一份场景大纲（每幕讲什么、用什么交互），确认后再写代码。

### 每个例子都要有背景页
书里的例子往往依赖业务背景（银团贷款、调漆、采购单……）。**每个例子之前插一页“例子背景”**，内容包括：
- 业务场景：这是什么公司、要解决什么问题；
- 关键术语表：例子里出现的专有名词各是什么意思；
- 一个引导问题：看动画时应该注意什么。

### 交互控件只在用得上的步骤出现
- 控件绑定到具体步骤（如 `ctrlSteps:[2]`），其他步骤隐藏。
- 不写“第 N 步起生效”这类提示，控件出现时就应当可以用。
- CSS 必须包含 `[hidden]{display:none!important}`，否则带 `display` 的类会让 `hidden` 失效。这个 bug 出现过一次。

### 文字
- 引文必须来自书本原文并标注章节，不要编造引文。
- 讲清“为什么”，不只是“是什么”；尽量用书中的原例。
- 侧栏文字和画面文字不要重复同一段内容。
- 中文排版：中英文之间留空格，术语首次出现时给出中英文。

## 页面技术约定

- 单文件，无构建依赖；外部资源只用 Google Fonts。
- 结构：Canvas 画面 + 侧栏说明 + 播放/暂停/上一步/下一步 + 分段进度条 + 悬停提示 + `#sN` 跳到第 N 幕。
- 明暗主题：颜色用 `:root` 变量定义，并在 `prefers-color-scheme: dark` 和 `[data-theme="dark"]` 下分别覆盖。
- 必须适配手机宽度（约 380px），不能出现横向滚动。
- 支持 `prefers-reduced-motion`。
- 开发时在 `/tmp/<slug>-build/` 里按文件拆分（head、helpers、每幕一个 js、engine），用脚本拼接成最终的 `index.html`，再复制进本仓库。
